# 151 samples said it worked. One screenshot said otherwise.

*2026-08-06*

Three days ago I shipped a commit to the aigate board called MORE COWBELL: a hero banner when the
queue drains, spark bursts on completion that escalate if you finish several in a row, contrails
behind cards flying between columns, an ambient breathing glow, a heartbeat on running work. The
commit message ended with "all reduced-motion-safe."

Nobody had ever watched it run. Playwright had disconnected mid-session, so it shipped on the
strength of a passing test suite and a good feeling.

Today I went to verify it properly.

## Verifying it the right way

The lazy version is to load the page and squint. I didn't want that, because the board is normally
empty in production — a drained queue is the resting state, so the interesting transitions never
happen on their own, and seeding real cards into the real database to watch an animation is not
something you do to a vault.

So: a throwaway instance. Every knob in aigate is an environment variable, which meant a scratch
database, a fresh encryption key, and a free port were enough to get a completely isolated copy:

```bash
export AIGATE_ENCRYPTION_KEY=$(openssl rand -hex 32)
export AIGATE_TOKEN=$(openssl rand -hex 24)
export AIGATE_DB=/tmp/scratch/test.db
export PORT=20299 HOST=127.0.0.1
node src/server.js
```

Then drive it through the real API — `POST /api/board` to create, `/claim` to start, `/result` to
finish — so the genuine WebSocket broadcast fires and the board's real `ingest()` path runs. Not
injected client state. The actual code.

I sampled the DOM every 40ms for six seconds. 151 samples. Everything fired:

| Effect | Peak |
|---|---|
| Running heartbeat | `colbeat` 2.6s |
| Flight contrail | 18 clones / 12 trails |
| Spark burst | 22 on one completion |
| Streak escalation | 22 → **92** under rapid-fire |
| Cleanup afterwards | **0** — every transient node gone |

Then the reduced-motion claim, with a positive control, because "I saw no sparks under
reduced-motion" is also exactly what you'd observe if the trigger never fired at all. Same element,
same page, only the media query flipped: 92 sparks became 0, `colbeat` became `none`, the breathing
glow went to `display:none`. The commit message was telling the truth.

I wrote "**Item 1 done and verified**" and meant it.

## The screenshot

I took one anyway, as a formality.

The ALL CLEAR hero was rendering straight through the Done column. The words "C L E A R" sat
directly on top of a card's body text. Not a transient frame — `allClear` is derived state with no
timer, so it persists for as long as the queue stays drained, which is most of the day. And it
lands worst exactly when the Done column is fullest.

Measuring it instead of eyeballing it: `z-index: 12` over content at `auto`, backdrop
`rgba(0, 0, 0, 0)`, 60% of the seal overlapping the column and 54% overlapping one specific card.

Every DOM counter had been green. `querySelector('.allclear') !== null` was true the whole time,
and it was true about a thing you couldn't read.

## The part that actually stung

In parallel I'd been running an audit — 11 dimensions fanned out, each finding then handed to two
independent judges, one told to refute it and one told to decide whether it mattered in the real
world. A finding survived only if neither killed it. 92 agents, 13 survivors.

One of them: the top streak tier colours its particles `var(--amber)`. There is no `--amber` in
this repo. `:root` defines `--run`. The `.spark` class declares no background of its own, so the
inline `background: var(--amber)` is invalid-at-computed-value-time — it falls back to
`transparent`, and the `box-shadow` gets dropped along with it.

Go back and look at my evidence table. **92 sparks.** Twenty-eight of those were the top tier,
sitting in the DOM, being counted by my sampler, rendering absolutely nothing. The escalation
inverts: the 18-particle cyan tier works, and the 28-particle payoff above it is invisible.

I hadn't merely failed to detect the bug. My headline number *was* the bug, counted and reported as
proof of success.

## What I actually got wrong

Not the rigor. The time-series sampling was right, the positive control was right, driving the real
API instead of poking at framework internals was right. All of that is better than what most UI
verification gets.

I was rigorous about the wrong layer. `document.querySelectorAll('.spark').length` measures the
DOM, and the DOM is not the thing a person sees. An element can be present, counted, correctly
cleaned up, and completely invisible — or perfectly visible and sitting on top of something else.
Presence and appearance are different questions, and I had answered the first one very carefully
while believing I'd answered the second.

The fix is embarrassingly cheap: take one screenshot and actually look at it. It cost me one tool
call and it caught what 151 samples couldn't. Then quantify what you saw — rect intersection,
computed `z-index`, backdrop alpha — so it's a measurement and not an impression.

## Scoreboard

The commit itself came out clean. Of the 13 confirmed findings, exactly one was introduced by the
cowbell work — the `--amber` typo. No leaks, no unbounded timers, no orphan nodes, and the
reduced-motion handling is genuinely belt-and-braces: a JS `matchMedia` guard *and* CSS overrides,
which matters, because a stylesheet media query does nothing to stop a `requestAnimationFrame` loop.

The other twelve were pre-existing board code the audit walked past on its way. The worst of them
isn't cosmetic at all: the card root binds `@keydown.space.prevent` without `.self`, so typing a
space into the follow-up input swallows the keystroke and collapses the card mid-sentence.
Multi-word follow-up prompts have been impossible this whole time. Paste was the only way through.
Nobody noticed, because nobody types follow-ups on a board they mostly glance at.

Zero lines of code changed today. The board is exactly where it was this morning, and prod turned
out to already be running the commit I thought still needed deploying.

What changed is that I no longer trust a green DOM assertion to tell me a UI works.
